# 题库分类与内容质量审计（2026-08-27）

## 结论

本轮已将 14 个题库的顶层分类收敛为 4 个学习方向，并将有效章节从 75 个合并为 50 个。762 道题的题目 ID 与顺序保持不变，因此现有学习进度、收藏和批注映射不会因分类调整而丢失。

四个学习方向为：

- 前端开发：5 个题库，300 题，16 个大章节。
- 后端开发：5 个题库，234 题，18 个大章节。
- AI 应用开发：2 个题库，75 题，8 个大章节。
- 求职专项：2 个题库，153 题，8 个大章节。

章节合并遵循“同一条学习主线连续阅读”的原则，每个题库保留 3–4 个大章节。合并只改变目录层级，不改变题目归属、ID 或顺序。

## 优先整改项

### P0：旧版“简历技术面试题”

该题库 81 题中，有 42 题正文不足 620 字、68 题无来源、60 题缺原理、59 题缺实践、68 题缺避坑。它是当前唯一明显低于全站标准的题库，应优先补齐来源、机制、验证场景和易错边界。

### P1：回答层级和可执行示例

- 360 专项不是信息不足，而是短回答过长：72 题中有 51 题的短回答超过 160 个非空白字符。应将首屏压缩为结论/选型，代码和推导移入“实践”段。
- Java 基础、Java 后端、Java + AI 共 149 题，概念和来源齐全，但缺少 fenced code。只为高价值工程题补最小 Java、SQL 或配置示例，例如 `equals/hashCode`、线程池、事务失效、MyBatis 参数、`ToolCallback` 和 `VectorStore`。
- 当前有 38 张图。对 Spring MVC、Bean 生命周期、HashMap 扩容、RAG/Agent、SSE 取消、TCP、MVCC、Redis 锁等高价值流程补 15–25 张图即可，不应为了“有图”给每题强行配图。
- SSE、RAG、Agent 等概念会合理地出现在前端、Java + AI 和岗位专项中。应增加“核心概念 → 工程/安全/岗位追问”的关联入口，而不是把它们机械搬进同一题库。

## 概念补充策略

不建议给每题添加重复的名词解释。更清晰的方案是在概念首次出现时显示一个可折叠“概念卡”，仅包含：

1. 一句话定义。
2. 适用边界。
3. 最容易混淆的相邻概念。
4. 对应的工程题、安全题和岗位题入口。

这样能补齐初学者所需背景，同时避免成熟读者反复看到同一段基础定义。

## Archify 适配结论

Archify 可用于本项目，但定位应是“上游作者工具”，而不是页面运行时依赖。

- 已固定并验证稳定版 `v2.15.0`，本机 Node.js 22 环境下 `doctor`、示例校验、交付校验、亮/暗主题和多尺寸视觉检查均通过。
- 它适合生成 RAG、Agent、MCP、SSE 重试等 8–12 节点的架构图、时序图和数据流图。
- 当前题库的安全策略只允许小于 100 KB、固定 1200×720、无脚本的静态 SVG；Archify 默认输出约 600 KB 的交互 HTML，不能直接嵌入题目。
- 推荐项目级固定 `v2.15.0`，通过受控导出脚本转为安全 SVG 后，再走现有尺寸和安全测试；不全局安装、不跟随 `main`、不允许模型自由决定输出路径。
- 官方已有关于输出路径覆盖风险的 issue，因此所有输出必须限制在项目的固定目录和固定扩展名中。

## 审计口径与限制

- “短回答过长”指移除 fenced code、图片、Markdown 修饰和空白后，仍超过 160 个非空白字符。
- “代码覆盖”只统计 CommonMark 行首的 fenced code，不把行内代码误计为示例。
- 当前 `source_refs.verified_at` 是内容导入时间，不等于来源 URL 在该时刻完成了 HTTP 可访问性校验。因此“有来源”只表示存在引用，不能解释为链接刚刚全部在线验证。
- 后续每轮题库更新都应执行 `npm run db:check`，让上述结构、来源和可读性指标成为可复现质量门槛。
