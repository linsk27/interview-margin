# 面试边注 · 产品界面重设计规范

> 版本：2026-08-04  
> 范围：保留现有题库、阅读、学习状态、批注、AI、账户和管理能力；重新组织入口、层级、阅读排版和响应式行为。

## 1. 设计结论

产品应从“工具全部常驻的后台界面”转为“内容优先的专注阅读器”。视觉气质定位为：安静、编辑感、可信、克制；强调长时间阅读，不追求大面积卡片、渐变或装饰性动效。

核心结构只有三层：

1. 全局导航：去哪个产品模块。
2. 当前题目：题库、章节、前后题和学习状态。
3. 上下文工具：题内目录、批注和 AI。

同一个动作在同一断点只保留一个入口。桌面和移动端可以互为响应式镜像，但不能同时出现。

## 2. 当前问题与处理决定

| 当前表现 | 决定 | 原因 |
| --- | --- | --- |
| Rail 与题库中心顶栏同时出现“学习概览、阅读设置” | 桌面端只保留 Rail；题库中心顶栏只在移动端显示全局动作 | 消除桌面重复入口 |
| Topbar `/` 与侧栏 `/` 都像“搜索题库” | 明确区分“搜索全部题库”和“筛选当前题库”；侧栏移除 `/` | 两者范围不同，不能使用相同文案与快捷键 |
| Rail 同时放页面、抽屉、模式、弹窗和账号 | 分为“导航 / 当前阅读 / 账户”三组，使用不同语义与状态 | 让用户知道点击后是跳页、展开还是切换模式 |
| 顶栏与题内导览在宽屏重叠 | 拆成两行：Topbar + Study Guide | 页面导航与滚动锚点不是同一层 |
| 单页/双页同时出现在顶栏和设置 | 保留一个快捷切换和一个完整设置，但共用同一组件与状态 | 这是合理的快捷入口，不是无意义重复 |
| 桌面 Rail 与 Topbar 都有题库/批注开关 | 保留，确保 CSS 断点互斥 | 这是桌面与移动端的响应式镜像 |
| 独立 AI 浮窗像客服，遮挡正文 | 改为可停靠、可缩放的右侧“上下文工作区” | AI 应围绕当前题目，而不是脱离内容 |
| 四个学习状态并列为主按钮 | 主动作收敛为“需复习 / 已掌握”；未开始和学习中自动显示 | 减少选择成本，符合实际学习动作 |

## 3. 桌面端信息架构

### 3.1 全局 Rail（64–72 px）

顶部：品牌。  
一级导航：题库、学习概览；管理员额外显示内容管理。  
当前阅读工具：复习队列、专注模式。  
底部：阅读设置、账户。

题库抽屉和批注抽屉的开关不再同时常驻于 Rail 和 Topbar；按断点各自只显示一处。页面入口使用 `aria-current`，抽屉使用 `aria-expanded`，模式使用 `aria-pressed`。

### 3.2 题库侧栏（300–340 px）

- 可完全收起，正文位置平滑过渡，不使用遮罩。
- 顶部显示题库短名、题目数和明确可见的收起按钮。
- 搜索框文案为“筛选当前题库”，不展示 `/`。
- 筛选项是 chips，不伪装成 tabs。
- 章节为可折叠列表；题目行只显示状态、编号和一行题目。
- 当前题使用左侧 2 px 强调线和极浅蓝底，不使用大色块。

### 3.3 顶部两层导航

第一行 Topbar（56–64 px）：

- 左：`题库短名 / 章节 / Qxx`。
- 右：搜索全部题库、收藏、上一题、下一题、阅读版式。
- 图标按钮统一 40 px 点击区域；同一组内 8 px 间距，组间 20–24 px。

第二行 Study Guide（44–48 px，sticky）：

- `速答 / 原理 / 实战 / 追问 / 避坑 / 来源` 是唯一一套题内目录。
- 随正文滚动高亮，点击只滚动内容，不创建新路由。
- 阅读进度明确标注为“本题”，不能只显示无语义百分比。
- 内容不存在的章节不显示；折叠章节被点击时先展开再定位。

### 3.4 正文列

- 默认宽度 760–820 px，最大 880 px；左右面板打开时仍保证至少 680 px。
- 正文字号 17 px，行高 1.8；标题使用思源宋体，界面控件使用思源黑体。
- 每段尽量不超过桌面端三行。长段拆成要点、步骤、对比表或流程图。
- 不在每一节之间放横线；用 40–56 px 的节间距建立层级。
- “速答”使用单个浅蓝强调面，不在其内部再套标签栏、卡片或竖向空白列。
- 只有复杂关系才使用图；概念差异用表；普通定义用列表。

### 3.5 右侧上下文工作区（380–440 px）

同一个面板承载“批注 / AI”两个标签页，避免批注抽屉与 AI 浮窗竞争层级。

- 面板停靠在正文右侧，可拖动宽度，可缩成 44 px 边缘入口。
- 打开面板不遮挡全局 Rail；宽度不足时压缩题库侧栏，最后才覆盖正文。
- 窄屏时左右抽屉不能同时打开。
- 层级固定为：全局导航 > 抽屉 > 遮罩 > 正文。

## 4. AI 学习助手

### 4.1 空状态

顶部显示 `AI 学习助手` 和范围标签 `仅当前题目 Qxx`。正文只保留一句能力说明和四个紧凑建议：

- 讲得更简单
- 画出流程
- 举真实例子
- 模拟追问

建议问题使用小型 chips，不使用四张大按钮卡。

### 4.2 对话状态

- 采用普通消息流，回答先给结论，再按需展开细节。
- 引用显示为 `原理 §2`、`代码 §1` 等小标签，点击定位原文。
- 输入框固定在底部，发送按钮内嵌；生成时替换为停止按钮。
- 单条回答操作只有：复制、重试、保存为批注。
- 游客可以提问；保存批注、保存对话、加入复习时再触发登录。
- 切换题目时提示上下文范围变化；不无提示地丢失正在编辑的输入。

## 5. 移动端结构

- 使用底部四项导航：题库、阅读、复习、我的。
- Reader 顶栏保留题库抽屉、当前 Q、收藏和更多；前后题使用正文底部或左右滑动。
- 题库抽屉与批注/AI 工作区一次只允许打开一个。
- 题库中心顶部提供全站搜索和账户，避免 Rail 隐藏后入口消失。
- AI/批注作为底部 sheet 打开，支持拖动到半屏与全屏。
- 正文边距 20 px；触控目标不小于 44 px；底部状态栏避让安全区。

## 6. 视觉系统

### 6.1 色彩

继续沿用纸张感中性色，减少边框：

- 页面：`#F5F7F9`
- 正文：`#FCFDFE`
- 主文字：`#142033`
- 次文字：`#667085`
- 品牌蓝：`#1769AA`
- 浅蓝强调：`#EAF3FC`
- 警示琥珀：`#B7791F`
- 分隔线：`rgba(20, 32, 51, 0.12)`

同一屏幕最多出现一个主要蓝色实心按钮。其他动作使用文字按钮或幽灵按钮。

### 6.2 字体与层级

- 阅读正文：Noto Sans SC / 思源黑体，17 px / 1.8，400。
- 正文标题：Noto Sans SC，24–40 px，600–700。
- UI 与导航：Noto Sans SC，13–15 px，500–700。
- 代码与编号：IBM Plex Mono，12–14 px。
- 全站使用同一套中文字体，仅通过字号与字重建立层级；代码区域保留等宽字体。

### 6.3 形状与动效

- 基础圆角 8 px；大面板 12 px；chips 999 px。
- 阴影只用于浮层，普通内容依靠背景差异和留白。
- 抽屉 220–260 ms；按钮 120–160 ms；尊重 `prefers-reduced-motion`。
- 禁止为了“高级感”加入大面积渐变、玻璃拟态、发光描边或无意义悬浮。

## 7. 题目内容模板

所有题目从第一题起逐步统一为：

1. 题目与考察点
2. 20 秒口述答案（60–120 字）
3. 核心机制（3–5 个短要点）
4. 原理图、流程图或对比表（仅关系复杂时）
5. 最小代码或真实场景
6. 常见误区
7. 面试官继续追问
8. 来源与版本边界

代码前说明“为什么需要它”，代码后补“运行结果 / 面试结论”。深入细节默认折叠为“展开深入原理”。

## 8. Figma 交付范围

独立设计文件建立以下可编辑页面：

1. `01 Foundations`：色彩、字体、间距、图标、交互状态。
2. `02 Components`：Rail、Topbar、Study Guide、题目行、状态控件、抽屉、AI 消息、输入框。
3. `03 Desktop`：题库中心、专注阅读、左右栏展开、AI 对话、批注。
4. `04 Mobile`：题库中心、阅读页、题库抽屉、AI/批注 sheet。
5. `05 States`：游客、登录用户、管理员、空状态、加载、错误、离线。

桌面主画板 1440×1024；移动主画板 390×844。组件必须使用 Auto Layout、变量和 variants，不能只交付扁平截图。

## 9. 实施顺序与验收

### 第一阶段：结构正确性

- hash/浏览器返回始终落到合法 workspace。
- 专注模式与抽屉状态解耦，退出后恢复此前布局。
- “继续学习”恢复题库中最近打开的题。

### 第二阶段：入口收敛

- 删除桌面题库中心重复的概览/设置。
- 明确全站搜索与当前题库筛选。
- 统一 responsive GlobalActions。
- 拆分 Topbar 与 Study Guide。

### 第三阶段：视觉与 AI

- 落实正文宽度、段落节奏、字体层级和少边框原则。
- 合并右侧批注与 AI 为上下文工作区。
- 完成桌面 1440、1280 和移动 390、320 四档视觉回归。

### 验收基线

- 一种动作在同一断点只有一个可见入口。
- 正文不会因任一侧栏打开而小于 680 px；移动端不出现横向滚动。
- 所有抽屉可主动收起，焦点返回触发按钮。
- 键盘可完成搜索、前后题、收藏、批注和 AI 输入。
- 游客可读题和使用临时 AI；持久化动作才要求登录。
- 关键组件具备空、载入、失败、禁用、聚焦和窄屏状态。

## 10. 参考与开源方案

产品模式参考：Readwise Reader、GitBook、NotebookLM、Linear、Anki 与 RemNote。它们共同支持“正文优先、低频工具收起、上下文搜索/AI、明确来源、单题聚焦”的方向。

建议的最小工程组合：

- Vercel Agent Skills：用 `web-design-guidelines` 与 `react-best-practices` 做设计/代码审查门禁。
- Radix Primitives：只为 Tabs、Dialog、Collapsible、Tooltip 和可访问抽屉等高风险交互增量采用。
- Storybook：覆盖组件状态矩阵、响应式和视觉回归。
- Anthropic `frontend-design`：作为视觉方向检查清单，不直接替代项目设计系统。

不建议当前全量迁移 shadcn/Tailwind；这会与现有 token 和手写 CSS 形成双设计体系。第三方 Agent Skill 也不应只因 star 数高就直接安装，安装前需审查内容与许可。
